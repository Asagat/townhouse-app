# Roadmap — Townhouse ERP

Сводный план развития проекта. Дата составления: август 2026.
Все изменения фиксируются в git (ветка `main`), каждое направление — отдельными коммитами.

---

## 1. Технический долг (из первоначального анализа)

| # | Задача | Обоснование / как |
|---|--------|-------------------|
| 1.1 | Разбить `backend/app.py` (~1700 строк) на модули | Единый файл содержит сериализаторы, конфиг полей (`FIELD_CONFIG`), билдеры и все роутеры. Разделить: `serializers.py`, `field_config.py`, `routers/{crud,registers,documents}.py`. Снижает риск регрессий и упрощает тесты. |
| 1.2 | Убрать или оживить `schemas.py` | Pydantic-модели сейчас не используются (API работает на голых `dict`) и разошлись с реальностью. Либо удалить, либо перевести ответы на эти модели. |
| 1.3 | Аутентификация и закрыть CORS | Сейчас `allow_origins=["*"]` + `allow_credentials=True` и нет вообще аутентификации. Перед продакшеном добавить: сузить CORS до реального домена (`townhouse.sagacloud.kz`), базовую/токенную аутентификацию. |
| 1.4 | Ввести миграции БД (Alembic) | Схема до сих пор правилась вручную (`ALTER TABLE`). Alembic даст воспроизводимые миграции и историю. |
| 1.5 | Серверная сортировка по вложенным полям | `hasattr(model, "owner.full_name")` всегда `False` → сервер молча сортирует по `id`. Для вложенных колонок добавить подзапросы (как уже сделано для квартиры и документа). |
| 1.6 | Почистить «осиротевшие» строки в БД | В `accounts_register` есть строки без привязки к `transaction_id`/`accrual_id` (артефакты до рефакторинга). Решить: удалить или привязать. |
| 1.7 | Проверить пересчёт балансов при массовых правках | Текущий пересчёт «с нуля» корректен, но добавить тесты и, при необходимости, репересчёт всех аккаунтов служебной командой. |

## 2. UX и функциональность

| # | Задача | Обоснование / как |
|---|--------|-------------------|
| 2.1 | Ресайз и перестановка колонок через библиотеку | Ручная реализация (HTML5 DnD) в AntD Table не заработала при `scroll={{x:'max-content'}}` и была удалена. Надёжно делается через `react-resizable` (ресайз) и `@dnd-kit` / `react-dnd` (перестановка). Требует добавления npm-зависимости. |
| 2.2 | Экспорт регистров и документов в Excel/CSV | Кнопки «Экспорт» в списках; выгрузка с учётом текущих фильтров/пагинации. |
| 2.3 | Отчёты по лицевым счетам | Начислено / оплачено / долг за период, сводка по дому. |
| 2.4 | Квитанции: создание, PDF, сохранение | ✅ Реализовано: модели `receipt_documents`/`receipt_items`, генерация по всем счетам за период, долг/переплата на «Фонд развития», PDF через `reportlab` (столбец «Переплата»), реализуем в UI (меню + ReceiptsModal). Осталось: выгрузка ZIP всех квитанций периода, при необходимости брендинг. |

## 3. Качество и надёжность

| # | Задача | Обоснование / как |
|---|--------|-------------------|
| 3.1 | Тесты бэкенда (pytest) | Покрыть расчёт начислений, пересчёт балансов `accounts_register`, CRUD. Защита от регрессий (напр., как с ресайзом, который нельзя было заметить без проверки в браузере). |
| 3.2 | Тесты фронтенда (vitest + RTL) | Ключевые сценарии GenericList: рендер, сортировка, модалки. |
| 3.3 | CI (при желании) | Прогон `tsc`, `build`, pytest и, опционально, lint при пуше. |
| 3.4 | Проверка и чистка накопленных данных | Аудит целостности `accounts_register` (балансы сходятся с историей), корректность названий документов. |

---

## Приоритеты (предлагаемый порядок)

1. **1.3 Аутентификация + CORS** — критично для продакшена.
2. **1.4 Alembic** — снимает ручное управление схемой.
3. **1.1 Распил `app.py`** — облегчает всё остальное и тесты.
4. **3.1 Тесты бэкенда** — фиксируют текущую логику начислений/балансов.
5. Остальное (UX 2.x, экспорт, отчёты, квитанции 2.4) — по мере необходимости.
