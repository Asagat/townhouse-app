# Решение ADR-001: выбор исходного стека архитектуры

- **Дата:** 2026-03-01
- **Статус:** принято

## Решение
Приняты FastAPI, React (фреймворк Refine), PostgreSQL и развёртывание через Docker внутри LXC-контейнеров Proxmox.

## Контекст
Требовалось быстрое, масштабируемое и сопровождаемое приложение для операционного управления.

## Почему это решение
Даёт строгую типизацию, высокую производительность, устойчивые асинхронные возможности API и готовую структуру администрирования интерфейса «из коробки».

# Решение ADR-002: драйвер PostgreSQL задаётся явно, версия SQLAlchemy ограничена

- **Дата:** 2026-09-26
- **Статус:** принято

## Решение
В `backend/database.py` драйвер задаётся явно (`postgresql+psycopg2://`) через `with_explicit_driver()`; в `backend/requirements.txt` SQLAlchemy ограничена `>=2.0,<2.1`.

## Контекст
В SQLAlchemy 2.1 дефолтным DBAPI для схемы `postgresql://` стал psycopg (v3), тогда как в проекте установлен `psycopg2-binary`. Свежая установка зависимостей (CI и сборка образа) ломалась на `import database`: `ModuleNotFoundError: No module named 'psycopg'` — CI упал на миграциях, а опубликованный образ `1.0.8` оказался неработоспособным (в нём SQLAlchemy 2.1.1).

## Почему это решение
Явный драйвер делает поведение независимым от версии SQLAlchemy (проверено на 2.0.54 и 2.1.1 в чистых контейнерах), а верхняя граница версии защищает от дальнейшего дрейфа unpinned-зависимостей. Снимать границу можно только после прогона CI и smoke-теста образа.
