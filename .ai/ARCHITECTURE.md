# Архитектура: Townhouse App

## Архитектура системы
- Клиент-серверная архитектура, разделяющая фронтенд на React (Refine) и надёжный бэкенд на FastAPI.
- Фронтенд — это интерфейс и предварительные предпросмотры; **все расчёты, проверки и состояние — на бэкенде** (см. `.ai/BUSINESS_RULES.md`).

## Компоненты и слои
- **Представление:** SPA на React (Refine) — `frontend/` (папки `pages/`, `components/`, `config/`, `auth/`).
- **Слой API:** роутеры FastAPI (`backend/routers/`) обрабатывают HTTP-запросы и ответы.
- **Слой бизнес-логики:** сервисные модули (`backend/services.py` и другие) инкапсулируют доменную логику и правила.
- **Слой доступа к данным:** модели SQLAlchemy (`backend/models.py`) и постоянное хранение в PostgreSQL.

## Зависимости и поток данных
- Запрос -> роутер -> сервис -> модель базы -> ответ.
- Изменение состояния и критические проверки выполняются строго в сервисах бэкенда.
- Учёт показаний и начислений построен по схеме «документ → регистр» (подробнее о полях и API — в корневом `PROJECT_STRUCTURE.md`).

## Схема и обоснования решений
- Изменение схемы — только через ревизии Alembic (`backend/migrations/README.md`).
- Принятые решения по стеку — `.ai/DECISIONS.md` (записи ADR).
