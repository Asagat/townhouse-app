# check_sum — контрольные тесты сверки «файл-источник ↔ БД»

Набор тестов, которые сверяют реальные регистры БД с файлом-источником переноса
(`templates/Миграция данных FTH.xlsx`). Запускать после любого data-переноса в прод
(и в development), чтобы убедиться, что групировки начислений, кассы и
взаиморасчётов не разошлись, а правила реклассификации/аннотаций не сломали итоги.

Тесты **только читают** БД (не изменяют данные).

## Состав

| Файл | Проверяет |
|------|-----------|
| `test_accruals_sums_method.py` | **Начисления** `accruals_register` vs Фиксированные/Переменные листы — 6 срезов: суммы по месяцу, месяц×услуга, месяц×квартира, итог, итог по квартире, итог по услуге (услуга через SRC_AN-канонизацию: Прочие→Фонд и т.п.) |
| `test_cash_slices_vs_source.py` | **Денежный регистр** `cash_register` vs «Касса-Приход»/«Касса-Расход»: приход по месяцу (нетто, сторно вычитается), расход по месяцу, приход по квартире × месяц |
| `test_registers_settlements_vs_cash.py` | **Взаиморасчёты** `accounts_register.expense` (= погашение долга от жительских взносов) vs «Касса-Приход» жителей: итог, по квартире, по месяцу, месяц × квартира |
| `test_cash_articles_pending.py` | **(xfail)** пункт «приход по статьям» — отложен: Код_Статья/Код_Аналитика файла не имеет прямого перс-соответствия статьям `analytic_articles` БД либо услугам долга `accounts_register` (платёж распределяется автоматически). Ждёт трактовку владельца; см. комментарии в файле. |

Вспомогательный модуль агрегирования начислений — `backend/migrations/accruals_sum_check.py`
(класс `AccrualsSumCheck`, standalone CLI `python migrations/accruals_sum_check.py`).

## Запуск

Нужен доступ к файлу-источнику и пакет `openpyxl` (есть в `backend/requirements.txt`):
если файл не лежит по пути по умолчанию (`templates/Миграция данных FTH.xlsx`
от корня репозитория), укажите переменную:

```bash
MIGRATION_SRC_XLSX=/path/Миграция\ данных\ FTH.xlsx \
  pytest backend/tests/check_sum -q
```

На пустой (CI) или неимпортированной БД тесты пропускаются (`skip`), чтобы набор
оставался зелёным; на импортированной dev/pre-prod — строгие проверки.
Ожидаемые эталоны (импорт dev, 09.2026): начисления Σ 60 122 992 ₸; касса-приход
Σ 60 401 744 ₸, кассы-расход Σ 60 039 094 ₸; взаиморасчёты Σ 58 688 903 ₸
(= жительский приход), Δ=0 на всех срезах.

## Ожидаемое поведение сборки

Прогон директории: `8 passed, 1 xpassed`. Пункт «по статьям кассы» (xfail)
проходит как xpass, пока трактовка не выбрана.
